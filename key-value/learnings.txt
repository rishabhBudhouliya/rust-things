# Aug 30th: Thinking about wire protocol for server-client communication

1. Why do I need a wire protocol?
2. I think I came up with a wire protocol for Atomic Pipe
2.1 That protocol involved a header (8 bytes) + fixed sized data chunk of bytes

3. Ok so couple of reasons why I'd need a wire protocol:
3.1 given that we communicate with bytes in a socket, we need a higher primitive that has the comfort of a boundary/identification that can be useful for users - like a message with predefined boundaries
3.2 it allows us to give ordering gaurantees
3.3 also allows to build other features on top of that (like congestion control/security)

Our data is key: string (growable), value: u32 (4 bytes)

4. Another consideration for wire format: operation (get/set/delete)
bytes(len(payload):op:[payload]

op = 1, 0 , -1
payload: keydelimetervalue


lengthopvaluekey

payload = bytes([len(payload)][key]:[value][key:value])
